# ADR-0116 — A post can be closed with an end date and no successor, without being archived

| Field | Details |
| --- | --- |
| **Status** | Accepted. Recorded 2026-09-26. Closes P1-2 in `docs/reviews/accounts-profiles-review.md`. |
| **Authority** | Product Owner brief, 2026-09-26 (decision F4). |
| **Amends** | `federationAppointments` gains an update path and a close route. |
| **Does not amend** | **`supersedesAppointmentId` and explicit succession** (confirmed decision #3, protected by brief §8): when a successor is named, exactly that one prior appointment is closed and no other. This ADR adds the case where there is no successor; it does not reinstate any implicit roleType-based auto-close. |
| **Context** | The only way to close an appointment is to create a successor that names it through `supersedesAppointmentId`. There is no `Update` permission and no `@Patch` route on the resource. So a board member who resigns with nobody replacing them leaves two options: the post stays `Active` for ever, or the row is archived through `DELETE` — and archiving hides the member from the archive that decision D4 says must remain. The status enum already contains `Resigned`, `Removed`, `Transitioned` and `Deceased`, but those values can only be written at creation time, so they describe a state the platform cannot actually reach. |
| **Decision** | `PATCH /federation-appointments/:id/close` taking `{ termEnd, status }`, with `status` from `Completed \| Resigned \| Removed \| Transitioned \| Deceased`. It writes those two fields and **nothing else** — no archival, and no other appointment touched. Service-level validation is added at the same time: committee roles require `committeeId`, and `President` and `BoardMember` require `electionCycleId`. |
| **Alternatives Considered** | **(A) A general `PATCH :id` and let the caller set `termEnd` and `status` among other fields.** Rejected as the closure mechanism: closing a term is a distinct act worth naming in the route, in the audit row and on the screen, and a general patch makes "this member resigned" indistinguishable from a typo correction. The general patch also arrives (ADR-0103 gives the resource `Update`), for editing a title or an order. **(B) Allow archival and treat it as closure.** Rejected: it is the current workaround and it contradicts D4 — the archive must stay readable. **(C) Require a successor always, even a placeholder.** Rejected: inventing a fictional appointment to record a real resignation puts false data in the governance record. **(D) Enforce the conditional requirements in the schema.** Rejected: the board's note explicitly states no schema-level conditional requirement, and the schema comment records that deliberately. Service-level validation respects that while still catching the error. |
| **Why This Decision** | The enum already said these states exist; only the route to reach them was missing. A dedicated close route keeps the act legible in the trail, which for a governance record is most of the point — "when did this person leave the board, and why" should be answerable from the appointment itself. |
| **Risks** | **A closure is used where a correction was meant**, ending a term that never ended. **Mitigation:** it is audited with the previous value, so `termEnd` and `status` can be read back and reversed by the general patch. **The conditional validation rejects existing rows on their next edit.** **Mitigation:** it validates the incoming change, not the stored row, so a legacy appointment missing `electionCycleId` is still editable; a report of non-conforming rows is logged in the backlog rather than enforced retroactively. **Closing the last active appointment of a role leaves a public page empty.** **Accepted and correct:** `currentLeadership` already returns an empty list so the section can disappear, and it is tested. |
| **Consequences** | `federationAppointments` gains `Update` in the capability map, a general `@Patch(':id')` and the dedicated `close` route. `FederationAppointmentsService` gains `close` and the two conditional checks. The four indexes of F2 land alongside, since closure queries filter on `personId` and `status`. |
