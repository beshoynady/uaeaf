# ADR-0117 — A person's official contact is published only when someone says so

| Field | Details |
| --- | --- |
| **Status** | Accepted. Recorded 2026-09-26. Resolves P0-2 in `docs/reviews/accounts-profiles-review.md`. |
| **Authority** | Product Owner brief, 2026-09-26 (decision F6), choosing the per-record switch. Inherits **Chapter 17 §1** (contact information is `Restricted`). |
| **Amends** | `federationPersonnel` gains `showPublicContact`, default **false**. The board page stops printing a `mailto:` unless it is true. |
| **Does not amend** | The `publicContact` / `internalContact` split, which stays exactly as it is — this adds a switch above it, not a replacement for it. · The rule that `toPublicResponse` is an allow-list. |
| **Context** | `publicContact` is documented `[PUBLIC]` — *"official public-facing contact only"* — and the structural exclusion of `internalContact` from the public DTO is sound: a distinct response class, built field by field, so a new schema field is not published by default. But visibility is a property of the **field**, not of the person: any record with an official email published it, and the board page rendered it as a live `mailto:` link. The only way to withhold one person's address was to not record it, which loses the data the federation holds for its own use. The brief's earlier expectation of a `showEmail` flag had no counterpart in the code. |
| **Decision** | A per-record `showPublicContact` boolean, **default `false`**, governing whether `publicContact` appears in any public response. Existing rows are set to `false` by a backfill script, so nothing already published stays published by accident. The public DTO omits the block entirely when the switch is off. |
| **Alternatives Considered** | **(A) Leave it as it is** — the field is `[PUBLIC]` by design, and whoever does not want publication does not record an address. Rejected: it makes recording an official contact and publishing it the same act, so the federation cannot hold a contact internally, and a routine data-entry step becomes a publication decision nobody framed as one. **(B) Remove contact from the public path entirely** and route everything through the contact form. Cheapest, and rejected: reaching a named officer directly is a real need for a federation, and the contact page already exists for the general case. **(C) Default the switch to `true` to preserve current behaviour.** Rejected, and this is the rejection that matters: Chapter 17 §1 classifies contact information as `Restricted`, so the safe default is withheld. Defaulting to `true` would also make the backfill a no-op and leave every existing address published — the exact state this ADR exists to end. **(D) One switch per field (email, phone).** Rejected as unnecessary granularity: no requirement distinguishes them, and two switches are two things to get wrong. |
| **Why This Decision** | Privacy-by-default is the standard the platform's own privacy chapter already sets, and a per-record switch is the smallest change that gives the federation both things it needs — a contact it can hold and a contact it chooses to publish. It also leaves the existing `[PUBLIC]`/`[RESTRICTED]` structure untouched, which brief §8 protects. |
| **Risks** | **Contacts the federation wants published disappear on deploy.** **Accepted and intended:** the backfill withholds everything, and an administrator turns on the ones that should be public. This is the conservative direction, and the reverse mistake — publishing an address nobody chose to publish — is not recoverable once indexed. **The switch is set and the page is cached.** **Mitigation:** the public read is cached for 60 seconds, so the change appears within that window; the plan's verification accounts for it rather than treating a stale read as a bug. **A future endpoint reads `publicContact` without checking the switch.** **Mitigation:** the check lives in `toPublicResponse`, the single mapper every public read goes through. |
| **Consequences** | `federationPersonnel` gains `showPublicContact` (default `false`). `toPublicResponse` omits `publicContact` when it is false. A `backfill-show-public-contact` script. `board-members-screen.tsx` renders the `mailto:` only when the block is present — which, combined with ADR-0118's change of source, is the second half of the board page fix. |
